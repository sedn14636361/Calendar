# カレンダー空き日程ボット

Googleカレンダーと連携し、Discord上で **予定の自動表示**・**空き日程の検索**・**月間カレンダー画像の出力** を行うDiscordボットです。

日程調整のたびにカレンダーを見比べる手間をなくすことを目的にしています。
「9月で夜が空いている日」をコマンド一つで一覧でき、結果はそのまま調整ツール（伝助など）に貼り付けられる形式でも出力できます。

| 機能 | 内容 |
|------|------|
| 予定の自動表示 | 今日から90日分をチャンネルに常時表示し、自動で更新 |
| 空き日程の検索 | `/2026-9` などのコマンドで、指定した期間の空き日を一覧 |
| 曜日での絞り込み | `/2026-9/sat/sun` のように、末尾で曜日を指定（複数可・順不同） |
| 月間カレンダー画像 | `/c2026-9` でその月の予定状況をPNG画像で出力 |
| コマンド一覧 | `/cmds` で使い方を表示 |

複数のGoogleカレンダー（仕事用とプライベート用など）をまとめて扱えます。

## まずはここから：ダウンロードしたらやること

### 1. ZIP を展開する

ZIP の中身を**フォルダごと**取り出します。ZIP を開いたままでは動きません。

### 2. ランチャーをダブルクリックする

展開したフォルダの直下にある、次のファイルをダブルクリックします。

| お使いの環境 | ダブルクリックするファイル |
|---|---|
| Windows | `start_wizard.bat` |
| macOS / Linux | `start_wizard.command` |

- 初回は準備に1分ほどかかります。2回目以降は数秒で起動します。
- Python 3.10 以上が必要です。入っていなければ入手先が表示されるので、
  [python.org](https://www.python.org/downloads/) から入れて、もう一度ダブルクリックしてください。
  Windows ではインストール時に「**Add python.exe to PATH**」に必ずチェックを入れてください。
- パソコンに元から入っている Python の設定は変えません。必要なものはこのフォルダの `setup` の中にだけ入ります。

> **macOS で「開発元を確認できない」と出た場合**は、
> `start_wizard.command` を**右クリック→「開く」**を選び、確認画面でもう一度「開く」を押してください。初回だけです。

### 3. ブラウザに開いたウィザードの指示に従う

ブラウザにセットアップウィザードが開きます。画面の案内に沿って進めると、
入力した値が本当に使えるかを、その場で Discord と Google に接続して確かめられます。

| ステップ | やること | その場で確かめること |
|---|---|---|
| 0. 準備 | ― | 必要なライブラリがそろっているか |
| 1. トークン | Discordボットを作る | トークンが有効か（ボット名を表示） |
| 2. INTENT | 設定を1つONにする | MESSAGE CONTENT INTENT がONか |
| 3. チャンネル | ボットをサーバーに招待する | チャンネルが見えるか。希望すればテスト送信 |
| 4. 鍵JSON | Googleの鍵を作る | 鍵で Google に認証できるか |
| 5. カレンダー | カレンダーを共有する | カレンダーが読めるか（カレンダー名を表示） |
| 6. 総合確認 | ― | 全項目を通しでもう一度 |
| 7. GitHub | 自分用のリポジトリを用意する | ― |
| 8. Render | 設定値を保存し、Render でボットを起動する | ― |
| 9. 常時稼働 | UptimeRobot を設定する | ― |

ステップ1〜6では、値を入力して「**この内容で確かめる**」を押します。
**確認がすべて OK になると「次へ」が表示されます。**
「要対応」や「判定不能」が出たときは、表示された直し方に沿って直し、もう一度押してください。
確かめたあとに値を書き換えると「次へ」は消えるので、もう一度確かめてください。

### 4. 後片付け

ステップ8で保存した設定ファイル（`calendar-bot-env.txt`）は秘密情報を含みます。
Render に貼り終えたら削除してください。

ウィザードは、30分間操作がないと自動で終了します。途中で止めるときは、ランチャーをダブルクリックしたときに開いた画面（Windows なら黒いウィンドウ）を閉じてください。

### Python を入れられない場合

`setup` フォルダの中の `wizard.html` をダブルクリックすると、同じ画面が Python なしで開きます。
ただし確かめられるのは**値の形**（鍵が途中で切れていないか、トークンに空白が混ざっていないか など）までです。
トークンが実際に通るか、鍵で Google に認証できるか、カレンダーが共有できているかは確かめられません。
このため「次へ」は、確認結果に「要対応」が無ければ表示されます。

### ウィザードを使わずに進める場合

この下の「第I部　セットアップ」が、ウィザードと同じ内容の手順です。

### 入力した値の扱い

ウィザードにはトークンや秘密鍵を入力します。

- 値はこのパソコンの外に出ません。確認のために Discord と Google へ接続するだけです
- ファイルにもログにも保存しません。ブラウザにも保存しないので、**ページを再読み込みすると入力は消えます**
- ウィザードは自分のパソコンからしか開けません。同じネットワークの他のパソコンからは接続できません
- ランチャーが書く記録（`setup/setup_log.txt`）には、Python の検出結果とライブラリの導入結果だけが入ります

### フォルダの中身

**操作するのは `start_wizard.bat`（または `start_wizard.command`）だけです。** ほかのファイルは触らなくて構いません。

```
（展開したフォルダ）
├── README.md              … この説明書
├── start_wizard.bat       … Windows でダブルクリックする
├── start_wizard.command   … macOS / Linux でダブルクリックする
├── Calendar.py            … ボット本体（Render で動かす）
├── requirements.txt       … ボットが使うライブラリの一覧（Render が読む）
├── LICENSE                … ライセンス
├── .gitignore             … Git 用の設定（GitHub に上げないファイルの一覧）
├── .gitattributes         … Git 用の設定（改行コードの扱い）
└── setup/                 … ウィザードの中身。直接触る必要はありません
    ├── wizard.html            … ウィザードの画面（Python が無いときはこれを直接開く）
    ├── setup_launcher.py      … ランチャーの中身
    ├── setup_wizard.py        … ウィザードを動かすプログラム
    ├── setup_checks.py        … 値を確かめるプログラム
    └── DEVELOPER_NOTES.md     … 開発者向けの資料
```

ランチャーを実行すると、`setup` フォルダの中に次の2つが作られます。直下のファイルは増えません。

| 作られるもの | 内容 |
|---|---|
| `setup/.venv` | ライブラリの置き場所。削除しても、次にランチャーを実行すれば作り直されます |
| `setup/setup_log.txt` | ランチャーの記録。うまく起動しないときに確認します |

ステップ8で保存する設定ファイル（`calendar-bot-env.txt`）は、ブラウザの保存先（通常は「ダウンロード」フォルダ）に保存されます。

# 第I部　セットアップ

ウィザードを使わずに手で進めるときの手順です。ウィザードの各ステップの詳しい説明としても使えます。

## 1. 全体像

```
Googleカレンダー ──(API)──> ボット(Python) ──> Discordチャンネルに表示
                                  ↑
                          Render（24時間稼働）
                                  ↑
                       UptimeRobot（スリープ防止）
```

ボットは自分のPCではなく Render（クラウド）上で動きます。PCを閉じても動き続けます。

## 2. 必要なもの

すべて無料で始められます。

- [ ] Discordアカウントと、ボットを入れるサーバー（自分が管理者のもの）
- [ ] Googleアカウント（表示したいカレンダーを持っているもの）
- [ ] GitHubアカウント
- [ ] Renderアカウント
- [ ] UptimeRobotアカウント
- [ ] PC（初期設定用。Windows / macOS / Linux）
- [ ] Python 3.10 以上（ウィザードで実際に接続して確かめる場合のみ）

この手順で取得する「鍵」や「ID」は次の4つです。あとで環境変数に入れます。

1. **Discord Bot トークン**
2. **Discord チャンネルID**
3. **Google カレンダーID**
4. **サービスアカウントの鍵JSON**（の中身）

## 3. Discord側の準備

### 3-1. ボットを作る
1. [Discord Developer Portal](https://discord.com/developers/applications) を開く
2. 「New Application」→ 名前を付けて作成
3. 左メニュー「Bot」→「Reset Token」でトークンを表示し、**コピーして控える** → `DISCORD_BOT_TOKEN`
4. 同じ画面で **「MESSAGE CONTENT INTENT」をON** にして保存（コマンドを読むのに必須）

### 3-2. ボットをサーバーに招待
1. 左メニュー「OAuth2」→「URL Generator」
2. SCOPES で **`bot`**、BOT PERMISSIONS で **`Send Messages`** にチェック
3. 生成URLをブラウザで開き、自分のサーバーを選んで招待

### 3-3. チャンネルIDを取得
1. Discordアプリ → 設定 →「詳細設定」→「開発者モード」をON
2. 表示したいチャンネルを右クリック →「チャンネルIDをコピー」 → `CHANNEL_ID`（数字のみ）

## 4. Googleカレンダー側の準備

ボットは「サービスアカウント」というボット専用のGoogleアカウントでカレンダーを読みます。

### 4-1. プロジェクトとAPIの有効化
1. [Google Cloud Console](https://console.cloud.google.com/) を開く
2. プロジェクトを新規作成
3. 「APIとサービス」→「ライブラリ」→ **Google Calendar API** を有効化

### 4-2. サービスアカウントと鍵の作成
1. 「APIとサービス」→「認証情報」
2. 「認証情報を作成」→「サービスアカウント」を**新しく作成**
3. 作成したものをクリック →「キー」タブ →「鍵を追加」→「新しい鍵を作成」→ **JSON**
4. ダウンロードしたファイルを `service_account.json` にリネームして保管
   → **中身（`{`〜`}` 全部）** が `SERVICE_ACCOUNT_JSON`

> ⚠️ この鍵ファイルは**絶対にGitHubに上げないでください**。チャットやメールにも貼らないでください。漏れるとカレンダーを読まれます。
> 漏れたかもしれないときは、同じ「キー」タブでその鍵を削除し、新しい鍵を作り直してください。

> 一覧に最初からある「Compute Engine default service account」（`…-compute@developer.gserviceaccount.com`）は使わず、
> このボット専用のサービスアカウントを作ってください。デフォルトのものはプロジェクト全体を編集できる権限を持っていることがあり、鍵が漏れたときの被害が大きくなります。

### 4-3. カレンダーを共有
1. JSON内の `client_email`（`xxx@プロジェクトID.iam.gserviceaccount.com` の形）をコピー
2. Googleカレンダー → 対象カレンダーの「設定と共有」
3. 「特定のユーザーやグループと共有」にその `client_email` を追加（権限は「予定の表示」でOK）
4. 同じ画面の「カレンダーの統合」にある **カレンダーID** をコピー → `CALENDAR_ID`

> 予定がボットに反映されないときは、**その予定がここで共有したカレンダーに入っているか**をまず確認してください。共有していないカレンダーの予定は見えません。

### 4-4. 複数のカレンダーをまとめて見る

1. **カレンダーごとに 4-3 を行う**（すべてのカレンダーを同じ `client_email` に共有する）
2. 得られたカレンダーIDを **「,」で区切って** `CALENDAR_ID` に入れる

```
CALENDAR_ID=aaa@group.calendar.google.com,bbb@group.calendar.google.com
```

改行区切りでも構いません。IDの前後の空白は自動で取り除かれます。

- 共有はカレンダーごとに必要です。**1つでも共有を忘れるとそのカレンダーは読めず**、コマンドの結果に警告が付きます（第III部参照）
- 空き日の判定は「**どれか1つのカレンダーにでも予定があれば埋まっている**」という扱いです

## 5. GitHub に上げてはいけないファイル

次のファイルは秘密情報を含むか、パソコンごとに作られるものです。GitHub に上げないでください。

| ファイル | 理由 |
|---|---|
| `service_account.json` | Googleの秘密鍵 |
| `calendar-bot-env.txt` | ウィザードが保存した設定値（トークンと秘密鍵を含む） |
| `setup/.venv` フォルダ | ランチャーが作るライブラリ置き場。大きく、他のPCでは使えない |
| `setup/setup_log.txt` | ランチャーの記録 |

Git で操作する場合は `.gitignore` で除外済みです。
**GitHub のサイトから「Upload files」で上げる場合は除外されない**ので、選ばないよう注意してください（8章）。

## 6. 環境変数の一覧

ローカルでもRenderでも、次の4つを設定します。

| 変数名 | 内容 | 取得元 |
|--------|------|--------|
| `DISCORD_BOT_TOKEN` | Discordボットのトークン | 3-1 |
| `CHANNEL_ID` | 表示先チャンネルのID（数字） | 3-3 |
| `CALENDAR_ID` | 表示するカレンダーのID（「,」区切りで複数可） | 4-3 / 4-4 |
| `SERVICE_ACCOUNT_JSON` | 鍵JSONの中身を丸ごと（`{`〜`}`） | 4-2 |

> `SERVICE_ACCOUNT_JSON` は最もつまずきやすい箇所です。**名前のスペル**と、**値が途中で切れていないか**（末尾が `}` で終わるか）を必ず確認してください。

## 7. 自分のPCで動かしてみる（省略可）

Render に上げる前に、自分のPCで動くか確かめたいときの手順です。
先に一度ランチャーを実行して、ライブラリを入れておいてください（`setup/.venv` に入ります）。
`service_account.json` は、展開したフォルダの直下（`Calendar.py` と同じ場所）に置き、
ターミナル（Windows は PowerShell）でそのフォルダに移動してから実行します。

macOS / Linux（ターミナルで、次を1つのコマンドとして実行）:

```bash
DISCORD_BOT_TOKEN="あなたのトークン" \
CHANNEL_ID="あなたのチャンネルID" \
CALENDAR_ID="あなたのカレンダーID" \
SERVICE_ACCOUNT_JSON="$(cat service_account.json)" \
setup/.venv/bin/python Calendar.py
```

Windows（PowerShell で、1行ずつ実行）:

```powershell
$env:DISCORD_BOT_TOKEN = "あなたのトークン"
$env:CHANNEL_ID = "あなたのチャンネルID"
$env:CALENDAR_ID = "あなたのカレンダーID"
$env:SERVICE_ACCOUNT_JSON = Get-Content service_account.json -Raw
setup\.venv\Scripts\python.exe Calendar.py
```

ログに `ログインしました: ...` が出れば成功です。止めるときは Ctrl+C を押します。

## 8. GitHubへのアップロード

Render は GitHub のリポジトリを読んで動かすので、まず自分のリポジトリを用意します。

**方法A：Fork（簡単）**

このリポジトリのページで右上の「Fork」を押すだけです。全ファイルが自分のアカウントにコピーされます。

**方法B：アップロード**

1. このリポジトリで「Code」→「Download ZIP」して、ウィザードを動かしたのとは**別の場所に**展開
2. [github.com](https://github.com) →「New repository」で自分のリポジトリを作成（公開・非公開どちらでも構いません）
3. 作成直後の画面の「uploading an existing file」（または「Add file」→「Upload files」）を開く
4. 展開したフォルダを開き、**中身をすべて選択して**ドラッグする
5. 「Commit changes」

> **フォルダそのものではなく、フォルダの中身をドラッグしてください。**
> フォルダごと上げるとリポジトリの中にもう1段フォルダができ、Render が `requirements.txt` を見つけられずに起動に失敗します。
> 上げたあと、リポジトリのトップページに `Calendar.py` と `requirements.txt` が直接並んでいれば正しい状態です。

> ランチャーを実行したフォルダには、`setup` の中に上げてはいけないファイル（`.venv`・`setup_log.txt`）ができています。
> 7章の手順を行った場合は、直下に `service_account.json` もあります（5章）。
> **ZIP を展開し直したばかりのフォルダから上げる**のが確実です。
> 上げたあと、一覧に `service_account.json`・`calendar-bot-env.txt`・`setup/.venv`・`setup/setup_log.txt` が無いことを確認してください。あれば削除します。

コードを直すときは、GitHub上でファイルを開き鉛筆アイコン（Edit）で編集 → Commit。Render が自動で反映します。

## 9. Renderへのデプロイ

1. [render.com](https://render.com) → GitHubで登録
2. 「New +」→「**Web Service**」→ 自分のリポジトリを接続
3. 設定：
   - **Build Command**：`pip install -r requirements.txt`
   - **Start Command**：`python Calendar.py`
   - **Instance Type**：Free
   - **Region**：任意（トラブル時はここを変える）
4. 「Environment Variables」で **6章の4つ**を追加
5. 「Create Web Service」で起動

「Logs」で `ログインしました: ...` が出れば成功です。発行される `https://〇〇〇.onrender.com` を控えておきます。

> Background Worker ではなく **Web Service** を選んでください。Background Worker には無料枠がありません。

## 10. UptimeRobotで常時稼働

Render の無料 Web Service は、15分アクセスがないとスリープします。UptimeRobot で定期的にアクセスして起こし続けます。

1. [uptimerobot.com](https://uptimerobot.com) で登録 →「Add New Monitor」
2. 設定：
   - **Monitor Type**：HTTP(s)
   - **URL**：Render の `https://〇〇〇.onrender.com`
   - **Monitoring Interval**：5 minutes
3. 「Create Monitor」

> Render のサービスを作り直してURLが変わったら、**UptimeRobot のURLも更新**してください。

⚠️ 無料枠と UptimeRobot の組み合わせは完全ではありません。まれに停止することがあります。
確実に常時稼働させたい場合は、Render の有料プラン（月7ドル程度）なども検討してください。

## 11. カスタマイズ

`Calendar.py` 上部の設定値を変えると挙動を調整できます。変更したら GitHub で Commit すると Render に反映されます。

| やりたいこと | 変える値 | 初期値 |
|---|---|---|
| 自動表示する日数 | `DAYS_TO_SHOW` | `90` |
| 昼の時間帯 | `DAY_START, DAY_END` | `10, 18`（10:00–18:00） |
| 夜の時間帯 | `NIGHT_START, NIGHT_END` | `18, 24`（18:00–24:00） |
| 自動更新の間隔 | `@tasks.loop(minutes=60)` の数字 | 60分 |
| タイムゾーン | `JST` | 日本時間（UTC+9） |
| 画像の色 | `IMG_BG`、`IMG_EVENT_COLOR`、`IMG_SUN`、`IMG_SAT` など | ― |

> 自動更新の間隔を短くしすぎると、Discord の利用制限（429 / 1015）にかかります。15〜60分にしてください。

# 第II部　利用法

> 💡 **コマンドを忘れたら `/cmds`** と打てば、いつでもコマンド一覧が表示されます。

## 12. 予定の自動表示

チャンネルには、**今日から90日先まで**の予定が自動で表示されます。

- 予定が入っている日はその内容が、入っていない日は「—」が表示されます
- 1時間ごとに確認し、予定や日付が変わっていれば表示を更新します
- 操作は不要です。見るだけでOKです

## 13. 空き日程を調べるコマンド

チャンネルにコマンドを打つと、その場で結果が返ってきます。

### 時間帯の定義

| 区分 | 時間帯 |
|------|--------|
| 昼 | 10:00 – 18:00 |
| 夜 | 18:00 – 24:00 |

「その時間帯に予定が1つでも重なっていれば、埋まっている」と判定します。

### 基本のコマンド

先頭の文字で、調べる時間帯が変わります。

| コマンド | 意味 |
|----------|------|
| `/2026-9` | **昼**が空いている日 |
| `/n2026-9` | **夜**が空いている日 |
| `/a2026-9` | **昼夜どちらも**空いている日（一日空いている日） |
| `/u2026-9` | **昼か夜のどちらか**が空いている日 |

> 月は1桁でもOKです（`/2026-9` でも `/2026-09` でも同じ）。

### 期間の指定

単月のほか、複数月や日単位の範囲でも調べられます。年をまたいでも指定できます。指定できる期間は最大12か月です。

| 書き方 | 意味 |
|--------|------|
| `/2026-9` | 2026年9月（1ヶ月） |
| `/2026-8:2026-9` | 2026年8月〜9月（月単位の範囲） |
| `/2026-8.15:2026-9.30` | 2026年8月15日〜9月30日（日単位の範囲） |
| `/2026-12:2027-1` | 年をまたいだ範囲 |

- 範囲の区切りは **`:`（コロン）**
- 日にちを指定するときは **`.`（ピリオド）** で月とつなぐ（例：`2026-9.15`）

### 反転（予定がある日を調べる）

末尾に **`r`** を付けると、「空いている日」ではなく「**予定がある日**」を出します。
反転が使えるのは **昼（無印）と夜（`n`）だけ**です。`a`・`u` に付けても無視されます。

| コマンド | 意味 |
|----------|------|
| `/2026-9r` | 昼に予定がある日 |
| `/n2026-9r` | 夜に予定がある日 |
| `/n2026-9:2026-10r` | 9〜10月で、夜に予定がある日 |

### 伝助形式で出す（日程調整用）

末尾に **`d`**（伝助のd）を付けると、空いている日を **1日1行・曜日つき** で出力します。
そのまま日程調整ツール（伝助など）に貼り付けられます。

```
9/9(水)
9/10(木)
9/11(金)
```

- すべてのモードで使えます：`/2026-9d`、`/n2026-9d`、`/a2026-9d`、`/u2026-9d`
- 範囲指定と組み合わせられます（例：`/n2026-9:2026-10d`）
- `r`（反転）と `d` は**同時には使えません**

### 曜日で絞る

コマンドのいちばん最後に **`/曜日`** を付けると、その曜日だけを出します。

| コマンド | 意味 |
|----------|------|
| `/2026-9/sat` | 9月で、**土曜**の昼が空いている日 |
| `/2026-9/sat/sun` | 9月で、**土日**の昼が空いている日 |
| `/2026-9/sat,sun` | 同じ（カンマ区切りでも書けます） |
| `/2026-9/土/日` | 同じ（日本語1文字でも書けます） |
| `/n2026-9d/fri/sat` | 9月で、金土の夜が空いている日を伝助形式で |
| `/2026-9r/mon` | 9月で、月曜に昼の予定がある日 |

使える書き方は次のとおりです。

```
mon  tue  wed  thu  fri  sat  sun
月   火   水   木   金   土   日
```

- **複数指定は `/` を重ねるだけ**です（`/sat/sun`）。カンマ区切り（`/sat,sun`）でも同じです
- **並べる順番は自由**です。`/sun/sat` と `/sat/sun` は同じ結果になります
- 英語と日本語を混ぜても構いません（`/土/sun`）
- 同じ曜日を重ねて書いても1回分として扱います。表記が違っても同じです（`/土,sat` は `/sat` と同じ結果）
- 先頭（`n`/`a`/`u`）・期間・末尾（`r`/`d`）と組み合わせられます
- **7曜日すべてを指定すると、曜日を書かなかったのと同じ結果**になります（見出しにも曜日は出ません）
- 該当する日が無ければ「該当する日はありません」と返ります
- 読めない語を書いた場合は、使える書き方を返します（例：`/2026-9/saturday`）
- **月間カレンダー画像（`/c`）では使えません。** 画像は月まるごとを描くためです

## 14. 月間カレンダー画像を出す

**`/c`** に続けて年月を打つと、その月の**カレンダー画像**が返ります。

| コマンド | 意味 |
|----------|------|
| `/c2026-9` | 2026年9月のカレンダー画像 |

各日のマスは上下2分割で、**昼が埋まっていれば上半分、夜が埋まっていれば下半分、両方なら全体**が水色に塗られます。日曜が赤、土曜が青です。

## 16. 出力の見かた

通常の結果は、月ごとに改行して表示されます。日付は各月の最初だけ「月/日」、以降は日にちだけになります。

```
2026/8/15〜2026/9/30
夜が空いている日（08/25現在）
8/15, 16, 20, 25
9/1, 2, 5, 12, 30
```

末尾の「〇〇現在」は、コマンドを送った時点の日付です。
伝助形式（末尾 `d`）のときは、装飾なしで日付だけが1行ずつ並びます。

# 第III部　エラー対処

## 17. よくあるトラブルと対処

**設定値が正しいか分からないときは、ランチャーからウィザードを起動し、「6. 総合確認」を実行してください。**
どこが問題かを名指しで表示します。

### セットアップ（ランチャー・ウィザード）

#### ダブルクリックしても窓が閉じるだけで何も起きない（Windows）
ダウンロードしたファイルが古いか、途中で壊れているときに起きます。
**まず ZIP を取り直してください。** 古いフォルダはまるごと削除してから展開してください。

エディタの設定によっては、`start_wizard.bat` を開いて保存し直しただけで同じ症状になることがあります。
その場合も ZIP を取り直してください。

それでも起きる場合は、`setup` フォルダ内の `setup_log.txt` を確認してください。
どこで止まったかが記録されています（トークンや秘密鍵は含まれません）。

#### ランチャーを実行すると文字化けしたエラーが並ぶ（Windows）
`start_wizard.bat` を編集して日本語を書き足した場合に起きます。
ZIP を取り直して、元のファイルに戻してください。

#### `A working Python was not found on this computer.` と出る／Microsoft Store が開く（Windows）
Python が入っていないか、Windows に最初から置かれている「名前だけの python」が使われています。
対処は2つあります。どちらか一方で構いません。

1. [python.org](https://www.python.org/downloads/) から 3.10 以上を入れる
   （インストール時に「Add python.exe to PATH」に必ずチェック）
2. 名前だけの python を無効にする——
   設定 → アプリ → アプリの詳細設定 → アプリ実行エイリアスで、
   `python.exe` と `python3.exe` をオフにする

#### 「この Python はバージョンが足りません」と出る
3.10 以上の Python を [python.org](https://www.python.org/downloads/) から入れて、もう一度ダブルクリックしてください。

#### 「ライブラリの取得に失敗しました」と出る
インターネットに繋がっているか確認して、もう一度ダブルクリックしてください。
繰り返し失敗する場合は、`setup` フォルダ内の `.venv` を削除してからやり直してください。

#### `error: externally-managed-environment`
ランチャーを使わずに `pip install` を実行したときに出ます。
**ランチャー（`start_wizard.bat` / `start_wizard.command`）を使えばこのエラーは出ません。**

#### ウィザードで「次へ」が表示されない
そのステップの確認がまだ OK になっていません。「この内容で確かめる」を押し、「要対応」「判定不能」と出た項目を、表示された直し方に沿って直してください。
すべて OK になると「次へ」が表示されます。

#### 「『1. トークン』で入力したトークンがありません」などと出る
前のステップで入力した値が消えています。入力した値は保存しないため、**ページを再読み込みしたり、ウィザードを起動し直したりすると消えます**。
表示されたステップに戻って入力し直し、「この内容で確かめる」を押してから、元のステップでもう一度確かめてください。

#### 「トークンが使えないため未検証」と出る
「1. トークン」のトークンが Discord に受け付けられていません。その上に表示されるトークンの結果を見て直してください。
Developer Portal で「Reset Token」を押すと、それまでのトークンは使えなくなります。最後に発行したトークンを使ってください。

#### 「Google がこの鍵を受け付けませんでした」と出る
鍵が削除されたか、サービスアカウントが削除されています。
Google Cloud Console でサービスアカウントの「キー」タブを開き、新しい鍵を作って、その中身を貼ってください（4-2）。

#### 鍵JSON の結果に「デフォルトのサービスアカウントです」と出る
Google が自動で作ったサービスアカウントの鍵を使っています。このままでも動きますが、4-2 の注意のとおり、専用のサービスアカウントを作って使う方が安全です。

### Render での起動

ボットが起動しないときは、Render の「Logs」に出ているエラーを見て、次から探してください。

#### `KeyError: 'SERVICE_ACCOUNT_JSON'`（など）
環境変数の設定漏れか、名前のスペルミスです。Render の「Environment」で4つ揃っているか確認してください（6章）。

#### `json.decoder.JSONDecodeError`
`SERVICE_ACCOUNT_JSON` の値が途中で切れています。鍵ファイルの `{`〜`}` を全選択でコピーし直してください。

#### `Improper token has been passed.`
`DISCORD_BOT_TOKEN` が間違っているか、前後に空白・改行が混ざっています。貼り直してください。

#### `ValueError: CALENDAR_ID にカレンダーIDが1つも入っていません`
`CALENDAR_ID` が空か、区切り文字と空白だけになっています。少なくとも1つのIDを入れてください。

#### `Could not open requirements file: ... 'requirements.txt'`
リポジトリのトップに `requirements.txt` がありません。アップロードのときにフォルダごと上げたため、1段深い場所に入っていることがほとんどです。
リポジトリのトップページに `Calendar.py` と `requirements.txt` が直接並ぶように、フォルダの中身だけを上げ直してください（8章）。

#### `ModuleNotFoundError: No module named ...`
ライブラリが入っていません。Render の **Build Command** が `pip install -r requirements.txt` になっているか確認してください（9章）。

#### `CERTIFICATE_VERIFY_FAILED`（自分のPCで動かしたとき）
PC側のSSL証明書の問題です。7章のコマンドの前に、次を実行してから起動してください（Render では起きません）。

```bash
export SSL_CERT_FILE="$(setup/.venv/bin/python -m certifi)"
```

### 使っているとき

#### コマンドに反応しない
- 書式（特に区切りの `:` と `.`）が正しいか確認してください
- `r` と `d` を同時に付けていないか確認してください（併用不可）
- Discord Developer Portal で **MESSAGE CONTENT INTENT** がONか確認してください（3-1）

#### 結果の末尾に「⚠️ 〇件のカレンダーを読み取れませんでした」と出る
`CALENDAR_ID` に指定したカレンダーのうち、読めないものがあります。結果は不完全なので、**そのまま日程調整に使わないでください**。
Render の Logs に `カレンダー読み取りエラー: <カレンダーID> -> ...` と出ているので、そのIDについて確認します。

- そのカレンダーを `client_email` に共有したか（**共有漏れが最も多い原因**です。4-4 参照）
- カレンダーIDの綴りに誤りや余分な文字がないか
- 区切りの「,」を入れ忘れて、IDがつながっていないか

Logs が `予定が多すぎて取りきれません` だった場合は別の原因です。そのカレンダーに、指定期間内の予定が約5万件以上あります。指定する期間を短くしてください。

#### 自動表示が更新されない（Logs に「更新を見送りました」と出る）
読めないカレンダーが1つでもある間、自動表示は**更新を見送ります**。
予定が抜けた不完全な表示で上書きしないためです。
上の項目でカレンダーを読めるように直せば、次の更新で自動的に戻ります。

#### 予定を変更・追加したのに反映されない
- その予定が、`CALENDAR_ID` に入れたカレンダーのどれかに入っているか確認してください。入れていないカレンダーの予定は見えません
- 自動表示は最大1時間遅れて更新されます。コマンドと画像は、実行した時点の最新の予定を使います
- 90日より先の予定は、自動表示には出ません（コマンドでは調べられます）

#### 結果が長すぎて途切れる
指定する期間を短くしてください。

#### `429 Too Many Requests`（Discord）
短時間にアクセスしすぎました。数分〜十数分待ってください。
自動更新の間隔を短くしている場合は、長くしてください（11章）。

Render の Logs に `You are being blocked from accessing our API temporarily` と出ている場合は、
**接続元のIPごと一時的に締め出されています**。Render の無料プランはほかの利用者とIPを共有しているため、
自分のボットがアクセスしすぎていなくても起きます。

- 締め出されると、ボットは応答の `Retry-After`（あと何秒待てばよいか）を読み取り、**その秒数＋10ミリ秒だけ待ってから、1回だけログインし直します**。
  Logs に「Retry-After に従い 〇〇 秒待ってから、1回だけログインし直します」と出ます。
  待っている間、Render ではサービスが動いているように見えます
- 再試行でも締め出されていた場合や、`Retry-After` が読み取れなかった場合は、それ以上は試みずに**エラーで終了します**。
  デプロイ直後なら、デプロイは失敗と表示されます
- エラーで終了したときは、**1時間ほど待ってから、Render で再デプロイまたは再起動してください**。Logs に `ログインしました: ...` と出れば復帰です
- 再デプロイや再起動を短い間隔で繰り返さないでください。ログインを試みるたびに、締め出しが長引きます
- Render がボットを自動で再起動することがあり、そのたびにログインを試みます。
  Logs に同じエラーが何度も出ている場合は、サービス画面の「Settings」→「Suspend Service」でいったん止め、
  1時間ほどおいてから「Resume Service」で再開してください
- 数時間たっても解けない場合は、下の `1015` と同じく、Render のサービスを別のリージョンで作り直してください
- 締め出されるたびに、Logs に「429 の応答ヘッダー:」として、Discord から返ってきたヘッダーが並びます。次の項目が手がかりになります

  | ヘッダー | 意味 |
  |---|---|
  | `Retry-After` | 締め出しが解けるまでの目安（秒）。`3600` なら約1時間 |
  | `X-RateLimit-Global` / `X-RateLimit-Scope` | Discord の利用制限（ボットごとの回数制限）による 429 のときに付きます。`Global` が `true` か `Scope` が `global` なら、このボット全体の制限です |
  | `Via` が無い、または `Content-Type` が `text/html` | 接続元のIPごとの締め出し（Cloudflare）です。下の `1015` と同じ対処をしてください |
  | `CF-Ray` | 問い合わせのときに使う識別番号です |

  ボットのトークンはログに出しません（ヘッダーは Discord からの応答のものだけで、Cookie も省いています）

#### Cloudflare `1015 / rate limited`（Discord）
接続元のIPが一時的にブロックされています。**ボットを止めて、数十分〜数時間待ってください**。
Render の共有IPが原因のこともあります。その場合は、Render のサービスを**別のリージョンで作り直す**と解決することが多いです。
作り直したら UptimeRobot のURLも更新してください（10章）。
